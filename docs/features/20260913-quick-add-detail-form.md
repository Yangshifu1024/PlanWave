# 提案：添加任务流程优化（回车后弹出详情表单）

- 日期：2026-09-13
- 状态：accepted
- 分支：`feature/quick-add-detail-form`
- 任务：`docs/tasks/feat-quick-add-detail-form/plan.md`

## 背景

当前的快速添加是「标题输入框 + 优先级下拉」：输入行内有一个原生 `<select>`（无/低/中/高），
回车即以默认值立即创建任务。问题：

- 优先级下拉占用输入行空间，且是创建时唯一可设置的字段；
- 想补充截止日期、备注、标签等详情，只能先创建再进详情面板逐项编辑，操作路径长。

## 需求

1. 移除添加任务文本框后的优先级选择。
2. 用户输入任务标题按回车后，弹出详细信息表单弹框。
3. 弹框提供「关闭」「保存」两个按钮；点击保存时校验表单内容。

## 方案要点（决策）

- **关闭 = 放弃创建**：点「关闭」/按 Esc/点遮罩均不创建任务；只有「保存」会创建。
  （备选的「关闭 = 仅用标题快速创建」被否决：二选一语义更直观。）
- **表单字段（精简版）**：标题（预填、可改）、优先级、截止日期、备注、所属项目
  （默认当前视图，智能视图 = 收集箱）、标签（逗号分隔）。复用 TaskDetail 的现成控件模式，
  重复规则等低频字段仍走详情面板。
- **保存校验 v1**：标题 trim 后非空；不通过时标题下方显示红色错误文案、聚焦标题框，
  不关闭弹框、不创建。
- 纯前端改动（`apps/web`），所有字段 `TaskPatch` 已支持，不涉及 Rust/同步层与 JSON 契约。

## 验收标准

- [ ] 输入行不再显示优先级下拉（`new-task-priority` 移入弹框）。
- [ ] 回车后弹出详情表单，标题预填输入内容。
- [ ] 点「保存」且标题非空 → 创建任务并关闭弹框。
- [ ] 点「保存」但标题为空 → 显示错误文案、不创建、弹框不关。
- [ ] 点「关闭」/Esc/遮罩 → 不创建任务。
- [ ] e2e 与单元测试更新并通过；`pnpm lint` / `pnpm typecheck` / `pnpm test:web` / `pnpm build:web` 全绿。
