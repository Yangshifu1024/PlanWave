# 提案：回收站彻底删除（单个 + 勾选批量）

- 日期：2026-09-13
- 状态：accepted
- 分支：`feature/trash-purge`
- 任务：`docs/tasks/feat-trash-purge/plan.md`

## 背景

回收站目前只能**恢复**软删任务（行内悬停「恢复」按钮 / 详情面板「从回收站恢复」）。
删除在系统中是软删墓碑（`deleted: true`），且：

- 服务端（memory/MySQL 两套 store）全部 upsert，不存在任何硬删除；
- IndexedDB 永不删单条任务记录（只有换服务器时的整库 reset）；
- `GET /sync/snapshot` **包含墓碑**——新设备登录会看到全部历史回收站，墓碑随时间无限累积；
- 内核不变量「回放 ≡ 快照」（`replay.rs`）决定了任何绕过 oplog 的清除都会被回放复活。

## 需求

回收站增加**单个删除**与**勾选批量删除**——即真·彻底删除。

## 决策（grilling 九问共识）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 删除语义 | 真彻底删除：全域（所有端+服务器）永久移除，不可恢复 |
| 2 | 同步协议 | forget op：oplog 新增「清除实体」事件；不做快照 epoch/GC |
| 3 | 子任务级联 | 级联删整棵树：所有后代（含正常视图可见的活子任务、回收站墓碑后代）一并永久删除 |
| 4 | 自动清理 | 不做；30 天自动清留作独立提案 |
| 5 | 勾选交互 | 行首选择框：回收站行首的「完成勾选框」替换为选择框 |
| 6 | 确认交互 | 确认弹框：单个/批量/清空均弹，显示条数与级联子任务数 |
| 7 | 配套能力 | 表头全选框 + 清空回收站按钮（不做批量恢复） |
| 8 | 墓碑小 UX | 墓碑行加删除线；详情面板对墓碑禁用「已完成」开关 |
| 9 | 单删入口 | 双入口：行内悬停按钮（恢复旁）+ 详情面板按钮 |

## 方案要点

- **协议**：oplog 新增 forget 事件。服务端投影删行 + 照记 op（不清历史）；老设备 pull 到
  forget 后删除本地记录；新设备回放（upsert…forget）自然消亡；快照因投影已删而自动排除。
  回放不变量「回放 ≡ 快照」保持。oplog 膨胀是既有独立问题（README 已列 compaction 为
  future work），不被本次恶化。
- **级联在客户端**：服务端是哑顺序器；web 端沿 `parent_id` 计算后代全集后逐实体发 forget
  op（每个 op 幂等、按 seq 全序传播）。确认弹框把级联数量摆到明面。
- **纯前端最小替代**（本端清除 / 仅批量恢复）因语义破洞被否决。

## 已知边界

- **级联竞态**：级联集合在确认时由本端当前任务列表计算；若其他设备在确认与服务端应用之间
  给该树新增子任务，该子任务不会被本次彻底删除波及，会以孤儿身份沿既有「孤儿上浮为顶层」
  逻辑继续可见。
- **forget 后的同实体编辑**：离线旧端迟到的编辑 op 会按 upsert 语义重建实体（全序回放的
  既有语义，非「复活」漏洞）；纯 UI 路径在彻底删除后不会产生该实体的编辑 op。
- oplog 历史（含 forget op）全部保留——回放正确性所需；compaction 仍是独立的后续项。

## 验收标准

- [ ] 回收站行内与详情面板均可对墓碑发起彻底删除，需确认；确认后任务从本端列表消失。
- [ ] 勾选批量删除（含表头全选、清空回收站）走同一确认流程。
- [ ] 级联：彻底删除父任务时其后代（含存活子任务）全部消失，确认框显示级联条数。
- [ ] 跨端：另一端手动刷新后被彻底删除的任务消失；新设备快照不再包含已彻底删除的任务。
- [ ] 墓碑行有删除线；详情面板对墓碑禁用「已完成」开关。
- [ ] Rust（merge/replay/json_interop/服务端 api）与 web（vitest/e2e）测试全绿。
